Сопоставление моделей телефонов и чёрных чехлов

Есть сопоставление → торговое предложение чехла + ЛАК для АВТО (0 руб.) · Нет → в заказе остаётся «Дизайн чехла» (это не авария)· Сумма всегда 45 руб.

1Суть задачи

Мы запускаем новый лендинг auto.caseme.by — там квиз: клиент указывает марку и модель своего автомобиля, модель телефона и госномер. Заявка уходит в RetailCRM как заказ.

Чтобы при запуске сразу работало корректное сопоставление, в состав заказа кладём конкретный чехол из нашего каталога + лак для АВТО (0 руб., входит в 45 руб.). Сейчас вместо понятной модели телефона в заказе стоит безликое «Дизайн чехла» — поэтому нужно сопоставить модель телефона с чехлом. Это и есть твоя задача.

После сопоставления заказ из квиза выглядит так

Заказ в RetailCRM

  • Позиция 1: чехол для модели клиента (45 руб.) — например, «Чехол для iPhone 17 силиконовый (Черный)»
  • Позиция 2: «ДОПОЛНИТЕЛЬНЫЕ УСЛУГИ | ЛАК для АВТО» (0 руб.)

Сумма заказа — 45 руб., как и было.

Важно: все данные заявки (модель телефона, авто, госномер) дублируются в полях «комментарий оператора» и «комментарий клиента» — так что даже без сопоставления заказ обработать можно. Но с сопоставлением склад и учёт работают правильно: списывается нужный товар.

Правило-мантра: есть сопоставление → торговое предложение чехла + ЛАК для АВТО (0 руб.). Нет → в заказе остаётся «Дизайн чехла» (это не авария). Сумма всегда 45 руб.

3Где работать — лист «разбор»

Никаких фильтров не нужно: в таблице есть лист «разбор» — там только строки, требующие обработки, отсортированные по приоритету брендов.

4Правила разбора

Читай колонку C в строке — там написано, какая из пяти ветвей твоя.

Если в C написано Кандидат один

Это чехол для модели — перенеси штрихкод из C в D и поставь ok в E. Готово.

Если в C написано Выбери кандидата с тем же токеном

4G и 5G — разные телефоны и разные чехлы. Токен модели (в B) указывает правильного кандидата. Выбери кандидата с тем же токеном → штрихкод в D, ok в E.

Если в C написано Кандидат, названный ТОЧНО как модель

Среди кандидатов ищи тот, в названии которого модель названа точно (например, «Чехол для Honor X8» для Honor X8). Нашёл → штрихкод в D, ok в E. Точного нет → не выбирай наугад: в F напиши ? уточнить: <что смущает>, E оставь пустой.

Если в C написано ⚠ Квиз …, у кандидата …

Токен модели не совпадает с токеном кандидата — возможна ошибка. Посмотри на название кандидата: если уверена, что это чехол для той же модели → штрихкод в D, ok в E. Если нет → F: ? уточнить, E пусто.

Если в C написано Поиск в RetailCRM

Чёрного чехла в автоподборе нет — но он может быть в каталоге CRM (каталог шире автовыгрузки; например, iPhone 12 там есть с фасоном «с вырезом»).

  1. Открой RetailCRM → раздел «Каталог» → поиск по фразе «Чехол для <модель>».
  2. Правила выбора среди результатов:
    • Точное совпадение названия модели приоритетно («Чехол для iPhone 12…» лучше комбо «iPhone 12 / iPhone 12 Pro…»; чужие модели — 12 Pro, 12 mini для «iPhone 12» — отбрасывай).
    • Комбо (чехол на несколько моделей) — подходит, если модель в названии есть.
    • «С вырезом» — другой фасон того же чехла, подходит.
    • Похожее из G («score …») — НЕ подставляй вслепую: это подсказка для поиска, а не готовый ответ (например, для iPhone 12 «похожее» — чехол от iPhone 13, он не подходит).
  3. Нашёлся чёрный чехол → штрихкод в D, ok в E.
  4. Не нашёлся → впиши в F ? нужен товар (добавим в МойСклад) или оставь строку пустой (заказ идёт как «Дизайн чехла»). Строки с «? нужен товар» собери списком — передай Дмитрию.

Никогда не выдумывай штрихкоды и не бери штрихкод от похожей модели (iPhone 12 ≠ iPhone 13; 4G ≠ 5G). Сомневаешься → F: ? уточнить.

5Когда закончишь

Сообщи Дмитрию: «разбор закончила» + список строк с F-вопросами (если есть). Обновление связи с заказами он сделает со своей стороны. Разобранные строки (D + ok) начнут попадать в заказы автоматически.

FAQ

Это авария, что часть заказов идёт с «Дизайн чехла»?
Нет. Заказ не теряется, все данные есть в комментариях; это временный режим до конца разбора.
Почему в каталоге есть «Черный» и «Прозрачный»?
В работе только чёрные; прозрачные в таблицу не попадают.
Что за «служебный оффер» в заказе?
У позиции без привязки к каталогу RetailCRM создаёт внутренний оффер — нормально для «Дизайн чехла».
Кому сообщать о проблемах и вопросах?
Дмитрию (владельцу): список строк с F-вопросами и строк «? нужен товар».

Правило-мантра: есть сопоставление → торговое предложение чехла + ЛАК для АВТО (0 руб.). Нет → в заказе остаётся «Дизайн чехла» (это не авария). Сумма всегда 45 руб.
